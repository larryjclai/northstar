## Findings considered and rejected (so nobody re-audits them)

- **`RelativeTime` "stale closure"** (`src/routes/settings/ConnectSection.tsx:79`) — not a
  bug. `iso` is read at render time; the effect only ticks `now` and never captures `iso`.
- **CORS `*` on the sync worker** (`worker/src/index.ts:58,130`) — not a vulnerability here.
  Auth is Bearer-token (no cookies), so a cross-origin page cannot read authenticated
  responses; `*` is the correct choice for a public API consumed by a native app.
- **Pairing `user_id` scoping / worker security headers** — downgraded to minor hardening:
  the claim path requires knowing the ephemeral on-screen pairing code, and the bundle is
  already E2E-encrypted under that code. Not worth a plan now.
- **IV reuse "what-if"** — `crypto.getRandomValues` is the standard source; folded into plan
  004 as an IV-uniqueness test rather than treated as a bug.
- **Floating-point TWR drift / date-string validation** — speculative, MED/LOW confidence;
  "investigate" leads, not confirmed bugs. Revisit only if a real discrepancy is observed.
